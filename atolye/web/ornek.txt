§EK 07-2
**Örnek — kısa filtre (tekrar ve boş):**
```csharp
public static IReadOnlyList<string> Temizle(IEnumerable<string> girdi)
{
    var gorulen = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
    var sonuc = new List<string>();
    foreach (var x in girdi)
    {
        var s = (x ?? "").Trim();
        if (s.Length == 0) continue;     // boşu atla
        if (gorulen.Add(s)) sonuc.Add(s); // ilk görüleni ekle
    }
    return sonuc;
}
```
`HashSet.Add` → yeni eleman ise `true`, zaten varsa `false` döner.

```
---
name: commit-yaz
description: Kullanıcı bir değişikliği commit etmek istediğinde kullan. Conventional Commits biçiminde kısa mesaj üretir.
---
1. `git diff --staged` ile değişikliği oku.
2. Tipi seç: feat, fix, docs, test, chore.
3. `tip: kısa açıklama` biçiminde tek satır yaz.
```
`description`'a "ne zaman kullanılır" yazmazsan Claude skill'i seçemez.

§EK 10-1
**Örnek A — `/acikla`:**
```
Şu kodu junior bir geliştiriciye anlatır gibi adım adım açıkla: $ARGUMENTS
```
**Örnek B — `/test-oner`:**
```
$ARGUMENTS dosyasını oku ve eksik kalan 5 test senaryosunu öner.
```
Dosya `.claude/commands/acikla.md` olursa komut `/acikla dosya.cs` olur.

§EK 10-2
**Örnek — Kod stili bölümü:**
```markdown
## Kod stili
- Sınıf ve metot adları Türkçe, PascalCase.
- Her public metoda en az bir test yaz.
- Sır koda yazılmaz; ortam değişkeni kullan.
```
İyi kural: kısa, emir kipi, doğrulanabilir.

§EK 10-3
**Örnek — iki sunucu:**
```json
{
  "mcpServers": {
    "dosyalar": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "./docs"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}
```
İki sunucu aynı `mcpServers` içinde, virgülle ayrılır. Token her zaman `${DEĞİŞKEN}`.
