§LAB 05 | RabbitMQ | C# koduyla RabbitMQ: bağlantı, kanal, kuyruk, mesaj gönder/al, exchange (direct, fanout, topic), ölü mektup.

§ADIM Bağlantı ve kanal nasıl açılır | cs
§ANLAT
**RabbitMQ nedir?** Ayrı çalışan bir **sunucu programı** (senin bilgisayarında Docker içinde, port 5672). Senin C# programın ona ağ üzerinden bağlanıp "şu kuyruğu aç, şu mesajı bırak" der. Kuyruk RabbitMQ'nun içinde yaşar, senin programının içinde değil.
```
 Senin C# programın                       RabbitMQ sunucusu
┌────────────────────┐   BAĞLANTI (TCP)   ┌──────────────────────┐
│  kanal 1  ─────────┼────────────────────┼─►  kuyruklar,        │
│  kanal 2  ─────────┼──── (tek hat) ─────┼─►  exchange'ler      │
└────────────────────┘                    └──────────────────────┘
```
İki kavram var, ikisini de **sen** açarsın:
- **Bağlantı (Connection):** RabbitMQ'ya açılan **tek bir ağ hattı** (TCP). Açması pahalıdır (kimlik doğrulama, el sıkışma), bu yüzden bir uygulama genelde **1 bağlantı** açar ve ömrü boyunca kullanır.
- **Kanal (Channel):** o hattın **içinden geçen hafif sanal hat**. Kuyruk açmak, mesaj yollamak, mesaj almak gibi **bütün işleri kanal üzerinden** yaparsın. Kanal açmak ucuzdur; bağlantı başına çok kanal açılabilir. (Kanalı aynı anda birden çok iş parçacığına paylaştırma.)

Neden iki katman? Her iş için yeni TCP hattı açmak yavaştır; bir hat + çok kanal hızlıdır. Bir benzetme: bağlantı = apartmanın giriş kapısı, kanal = dairelerin kendi kapıları.

Kodda 3 adım:
1. `ConnectionFactory`: bağlantı **ayarları** (adres, kullanıcı, parola). Bağlanmaz, sadece tarif eder.
2. `CreateConnectionAsync()`: gerçekten **bağlanır**.
3. `CreateChannelAsync()`: bağlantının içinde **kanal** açar.

`await using` = "iş bitince otomatik kapat". Yeni RabbitMQ.Client (v7) tamamen **async**'tir, bu yüzden her çağrının başında `await` var.

Sayfada hazır olan: `KULLANICI` ve `SIFRE` sabitleri (gerçek parolayı koda yazmak zorunda kalmayasın diye).
§ORNEK
var f = new ConnectionFactory { HostName = "localhost", UserName = KULLANICI, Password = SIFRE };
await using var hat = await f.CreateConnectionAsync("atolye-demo");
await using var k1 = await hat.CreateChannelAsync();
await using var k2 = await hat.CreateChannelAsync();
Console.WriteLine($"Bağlantı adı: {hat.ClientProvidedName}");
Console.WriteLine($"Aynı hatta iki kanal: no {k1.ChannelNumber} ve no {k2.ChannelNumber}");
§GOREV
1) `fabrika` adlı bir `ConnectionFactory` oluştur: `HostName = "localhost"`, `UserName = KULLANICI`, `Password = SIFRE`. 2) `await using var baglanti = await fabrika.CreateConnectionAsync();` 3) `await using var kanal = await baglanti.CreateChannelAsync();` 4) Ekrana yazdır: `Bağlantı açık mı: ...` (`baglanti.IsOpen`) ve `Kanal açık mı: ..., kanal no: ...` (`kanal.IsOpen`, `kanal.ChannelNumber`).
§BASLANGIC
// 1) bağlantı ayarları (ConnectionFactory)

// 2) bağlan (CreateConnectionAsync)

// 3) kanal aç (CreateChannelAsync)

// 4) açık mı diye ekrana yazdır

§K Parola: SIFRE ⟫ /Password\s*=\s*SIFRE\b/ ⟫ Password = SIFRE
§K Bağlantı açıldı ⟫ /await\s+using\s+var\s+\w+\s*=\s*await\s+\w+\.CreateConnectionAsync\(\s*\)/ ⟫ await using var baglanti = await fabrika.CreateConnectionAsync();
§K Kanal açıldı ⟫ /await\s+using\s+var\s+\w+\s*=\s*await\s+\w+\.CreateChannelAsync\(\s*\)/ ⟫ await using var kanal = await baglanti.CreateChannelAsync();

§ADIM Kuyruk oluştur ve mesaj gönder | cs
§ANLAT
**Kuyruk** RabbitMQ'nun içindeki **bekleme sırasıdır**: mesaj gelir, sıraya girer, biri alıp işleyene kadar bekler (ilk giren ilk çıkar). Kuyruğu `QueueDeclareAsync` ile oluşturursun. "Declare" (bildir) demek: **yoksa oluştur, varsa aynı ayarlarla olduğunu doğrula**; yani iki kez çalıştırmak güvenlidir.
```csharp
await kanal.QueueDeclareAsync(queue: "atolye.siparis", durable: true, exclusive: false, autoDelete: false);
```
| Parametre | Anlamı |
|---|---|
| `queue` | kuyruğun adı |
| `durable: true` | RabbitMQ yeniden başlasa da **kuyruk kalsın** (diske yazılır) |
| `exclusive: false` | yalnızca bu bağlantıya özel olmasın, başkaları da kullanabilsin |
| `autoDelete: false` | son tüketici ayrılınca kuyruk silinmesin |

**Mesaj gönderme:** `BasicPublishAsync`. Mesajın gövdesi **byte dizisidir**, o yüzden önce metni `Encoding.UTF8.GetBytes("...")` ile byte'a çevirirsin.
```csharp
await kanal.BasicPublishAsync(exchange: "", routingKey: "atolye.siparis", body: govde);
```
`exchange: ""` = **varsayılan exchange**. Bu özel exchange, mesajı `routingKey` ile **aynı adlı kuyruğa** yollar. Yani "doğrudan kuyruğa" gönderiyormuş gibi davranır.

**Sayma tuzağı:** `BasicPublishAsync` mesajı yolladıktan sonra RabbitMQ'nun kuyruğa koymasını **beklemez** (ateşle ve unut). Hemen sayarsan eksik görebilirsin; sayıdan önce `await Task.Delay(500);` koyarız. (Gerçek uygulamada bunun yerine "publisher confirms" kullanılır.)

Kuyruktaki mesaj sayısını görmek için `QueueDeclarePassiveAsync("ad")` kullan ("sadece bak, oluşturma"); dönen nesnenin `MessageCount` alanı bekleyen mesajdır.

Sayfada senin yerine **hazır yazılan** kod (bağlantı ve kanal, önceki adımdan):
```csharp
var fabrika = new ConnectionFactory { HostName = "localhost", UserName = KULLANICI, Password = SIFRE };
await using var baglanti = await fabrika.CreateConnectionAsync();
await using var kanal = await baglanti.CreateChannelAsync();
```
§ORNEK
await kanal.QueueDeclareAsync(queue: "atolye.demo", durable: true, exclusive: false, autoDelete: false);
await kanal.BasicPublishAsync(exchange: "", routingKey: "atolye.demo", body: Encoding.UTF8.GetBytes("ilk mesaj"));
Console.WriteLine("Mesaj gönderildi.");
await Task.Delay(500);
var durum = await kanal.QueueDeclarePassiveAsync("atolye.demo");
Console.WriteLine($"Kuyrukta bekleyen mesaj: {durum.MessageCount}");
§GOREV
`atolye.siparis` adlı **durable** kuyruğu oluştur. `siparis-1` ve `siparis-2` mesajlarını sırayla gönder (varsayılan exchange, `routingKey` = kuyruk adı); her gönderimde `Gönderildi: ...` yazdır. Sonra `await Task.Delay(500);` ile bekle ve `QueueDeclarePassiveAsync` ile bekleyen mesaj sayısını `Kuyrukta bekleyen mesaj: ...` diye yazdır (2 çıkmalı).
§BASLANGIC

// 1) kuyruğu oluştur (QueueDeclareAsync)

// 2) iki mesajı gönder (BasicPublishAsync, gövde: Encoding.UTF8.GetBytes)

// 3) kısa bekle, sonra kuyruktaki mesaj sayısını yazdır (QueueDeclarePassiveAsync)

§K Gövde byte dizisine çevrildi ⟫ /Encoding\.UTF8\.GetBytes\(/ ⟫ Encoding.UTF8.GetBytes(mesaj)
§K Varsayılan exchange + kuyruk adı anahtar ⟫ /BasicPublishAsync\(\s*(exchange:\s*)?""\s*,\s*(routingKey:\s*)?"atolye\.siparis"/ ⟫ BasicPublishAsync(exchange: "", routingKey: "atolye.siparis", body: govde)

§COZUM

§ADIM Mesaj al: BasicGet ve Consumer + ack | cs
§ANLAT
Mesajı **iki yolla** alabilirsin:
1. **Çekme (pull) — `BasicGetAsync`:** "kuyrukta mesaj var mı?" diye **sen sorarsın**, tek mesaj gelir (ya da `null`). Basit, ama sürekli sormak gerekir. Test ve küçük işler için.
2. **Dinleme (push) — Consumer:** bir **tüketici** kaydedersin; RabbitMQ yeni mesaj geldikçe **sana yollar**, senin kodun her mesajda çalışır. Gerçek uygulamalar böyle çalışır.

**Ack (onay) şart:** `autoAck: false` dersen RabbitMQ mesajı **silmez**; "bunu işledim" anlamında `BasicAckAsync(ea.DeliveryTag, multiple: false)` bekler. `DeliveryTag` mesajın o kanaldaki **numarasıdır** ("şu numaralı mesajı işledim"). Ack gelmeden kanal kapanırsa mesaj **kuyruğa geri döner**: işin kaybolmaması bununla sağlanır.

Consumer'ın 3 parçası:
```csharp
var tuketici = new AsyncEventingBasicConsumer(kanal);        // 1) tüketici nesnesi
tuketici.ReceivedAsync += async (_, ea) => { ... };            // 2) mesaj gelince ne yapılacak
await kanal.BasicConsumeAsync(kuyruk, autoAck: false, consumer: tuketici);  // 3) dinlemeyi başlat
```
- `ReceivedAsync` bir **olaydır**; `+=` "mesaj gelince şu kodu çalıştır" der.
- `(_, ea)`: ilk parametre göndereni (kullanmıyoruz, `_`), `ea` mesajın kendisidir (`ea.Body` gövde, `ea.DeliveryTag` numara).
- Gövde `ReadOnlyMemory<byte>` gelir: `Encoding.UTF8.GetString(ea.Body.ToArray())` ile metne çevrilir.

Sayfada senin yerine **hazır:** bağlantı + `kanal` ve `atolye.is` kuyruğu (`kuyruk` değişkeni); içinde 3 mesaj (`siparis-1..3`) bekliyor. Kodun bitince 1,5 sn beklenir, kanal kapatılır ve kuyrukta kaç mesaj kaldığı yazılır: **ack vermediysen mesajlar geri döner.**
§ORNEK
var tuketici = new AsyncEventingBasicConsumer(kanal);
tuketici.ReceivedAsync += async (_, ea) =>
{
    var govde = Encoding.UTF8.GetString(ea.Body.ToArray());
    Console.WriteLine($"[örnek] {govde} ({govde.Length} karakter) numara={ea.DeliveryTag}");
    await kanal.BasicAckAsync(ea.DeliveryTag, multiple: false);
};
await kanal.BasicConsumeAsync(kuyruk, autoAck: false, consumer: tuketici);
§GOREV
Önce `BasicGetAsync(kuyruk, autoAck: false)` ile **tek** mesaj çek; `null` değilse `BasicGet ile alındı: ...` yazdır ve `BasicAckAsync(tek.DeliveryTag, multiple: false)` ile onayla. Sonra `tuketici` adlı `AsyncEventingBasicConsumer(kanal)` oluştur; `ReceivedAsync` içinde mesajı metne çevir, `Consumer ile alındı: ...` yazdır ve ack ver. En sonda `BasicConsumeAsync(kuyruk, autoAck: false, consumer: tuketici)` ile dinlemeyi başlat.
§BASLANGIC

// 1) çekme: tek mesaj al (BasicGetAsync), yazdır, ack ver

// 2) dinleme: consumer oluştur

// 3) ReceivedAsync: oku, yazdır, ack

// 4) dinlemeyi başlat (BasicConsumeAsync)

§K BasicGetAsync ile çekme ⟫ /BasicGetAsync\(\s*kuyruk\s*,\s*autoAck:\s*false\s*\)/ ⟫ var tek = await kanal.BasicGetAsync(kuyruk, autoAck: false);
§K Çekilen mesaj ack'lendi ⟫ /BasicAckAsync\(\s*\w+\.DeliveryTag\s*,/ ⟫ await kanal.BasicAckAsync(tek.DeliveryTag, multiple: false);
§K Consumer nesnesi ⟫ /new\s+AsyncEventingBasicConsumer\(\s*kanal\s*\)/ ⟫ var tuketici = new AsyncEventingBasicConsumer(kanal);
§K ReceivedAsync olayı ⟫ /\.ReceivedAsync\s*\+=/ ⟫ tuketici.ReceivedAsync += async (_, ea) => { ... };
§K Gövde metne çevrildi ⟫ /Encoding\.UTF8\.GetString\(\s*\w+\.Body\.ToArray\(\)\s*\)/ ⟫ Encoding.UTF8.GetString(ea.Body.ToArray())
§K Consumer içinde ack verildi ⟫ /BasicAckAsync\(\s*ea\.DeliveryTag\s*,/ ⟫ await kanal.BasicAckAsync(ea.DeliveryTag, multiple: false);
§K Dinleme başlatıldı (autoAck: false) ⟫ /BasicConsumeAsync\(\s*kuyruk\s*,\s*autoAck:\s*false\s*,\s*consumer:\s*\w+\s*\)/ ⟫ await kanal.BasicConsumeAsync(kuyruk, autoAck: false, consumer: tuketici);
§COZUM

§ADIM Exchange oluştur ve yönlendir (direct) | cs
§ANLAT
Şimdiye kadar mesajı varsayılan exchange ile doğrudan kuyruğa yolladın. Gerçekte gönderen **kuyruğu bilmez**; mesajı bir **exchange**'e (dağıtıcı/postacı) bırakır. Exchange, **kurala** bakıp mesajı doğru kuyruğa koyar.
```
                          ┌─ kural (binding): "kargo"  ──► [atolye.kargo]
paket-1 ──► [exchange] ───┤
(etiket=kargo)            └─ kural (binding): "fatura" ──► [atolye.fatura]
```
Üç kavram, üç kod satırı:
1. **Exchange oluştur:** `ExchangeDeclareAsync(exchange: "atolye.siparisler", type: ExchangeType.Direct, durable: true)`.
2. **Kural (binding):** `QueueBindAsync(queue: "atolye.kargo", exchange: "atolye.siparisler", routingKey: "kargo")` = "bu exchange'e `kargo` etiketiyle gelen mesajı `atolye.kargo` kuyruğuna koy".
3. **Gönder:** `BasicPublishAsync(exchange: "atolye.siparisler", routingKey: "kargo", body: ...)`. `routingKey` mesajın üstündeki **adres etiketidir**.

`ExchangeType.Direct` = etiket kuralla **birebir** eşleşirse yönlendir. Eşleşmezse? **Mesaj sessizce kaybolur**: hata yok, uyarı yok. Bu atölyede bunu kanıtlayacaksın: yanlış etiketli mesaj hiçbir kuyruğa girmez.

Sıra önemli: **önce exchange ve kuyruk, sonra binding, en son mesaj.** Binding'den önce gönderirsen mesaj kaybolur.
§ORNEK
await kanal.ExchangeDeclareAsync(exchange: "atolye.demo-ex", type: ExchangeType.Direct, durable: true);
await kanal.QueueDeclareAsync("atolye.demo-odeme", durable: true, exclusive: false, autoDelete: false);
await kanal.QueueBindAsync(queue: "atolye.demo-odeme", exchange: "atolye.demo-ex", routingKey: "odeme");
await kanal.BasicPublishAsync(exchange: "atolye.demo-ex", routingKey: "odeme", body: Encoding.UTF8.GetBytes("tutar-100"));
await kanal.BasicPublishAsync(exchange: "atolye.demo-ex", routingKey: "yanlis", body: Encoding.UTF8.GetBytes("kayip"));
await Task.Delay(500);
Console.WriteLine($"odeme kuyruğu: {(await kanal.QueueDeclarePassiveAsync("atolye.demo-odeme")).MessageCount} mesaj");
§GOREV
`atolye.siparisler` adlı **Direct** exchange oluştur. İki durable kuyruk aç: `atolye.kargo`, `atolye.fatura`. İki binding kur: `kargo` etiketi → `atolye.kargo`, `fatura` etiketi → `atolye.fatura`. Exchange'e `kargo` etiketiyle `paket-1`, **yanlış** etiketle (`yok`) `kayip` gönder. `Task.Delay(500)` sonrası iki kuyruktaki mesaj sayısını yazdır (kargo 1, fatura 0 çıkmalı; `kayip` hiçbir yerde yok).
§BASLANGIC

// 3) iki binding (QueueBindAsync): kargo -> atolye.kargo, fatura -> atolye.fatura

// 4) iki mesaj: etiket "kargo" (paket-1) ve etiket "yok" (kayip)

// 5) bekle, sonra iki kuyruğun mesaj sayısını yazdır

§ADIM Fanout: bir olay, birçok alıcı | cs
§ANLAT
Bazen **aynı olayı birden çok servis** öğrenmelidir: "kullanıcı kaydoldu" → e-posta servisi hoş geldin yazsın **ve** istatistik servisi sayacı artırsın. Gönderen kimlerin dinlediğini bilmez, bilmesi de gerekmez.
```
                        ┌──► [atolye.eposta]
yeni-uye ──► [fanout] ──┤
                        └──► [atolye.istatistik]
```
`ExchangeType.Fanout` etikete **bakmaz**; kendisine bağlı **bütün** kuyruklara mesajın **birer kopyasını** koyar (fan = yelpaze). Yeni bir servis eklemek için sadece yeni bir kuyruk bağlarsın, **gönderen kod hiç değişmez**.

Binding'de etiket gerekmez ama `QueueBindAsync` parametresi zorunlu olduğu için boş verirsin: `routingKey: ""`.

Direct ile farkı: direct "etiket tutarsa", fanout "herkese".
§ORNEK
await kanal.ExchangeDeclareAsync("atolye.demo-yayin", ExchangeType.Fanout, durable: true);
foreach (var ad in new[] { "atolye.demo-sms", "atolye.demo-log", "atolye.demo-rapor" })
{
    await kanal.QueueDeclareAsync(ad, durable: true, exclusive: false, autoDelete: false);
    await kanal.QueueBindAsync(queue: ad, exchange: "atolye.demo-yayin", routingKey: "");
}

§ADIM Topic: desenle yönlendir | cs
§ANLAT
**Topic** exchange, etiketi **noktalı kelimelerle** yazdırır (`odeme.hata`, `stok.bilgi`) ve binding'de **desen** kullandırır:
- `*` = tam **bir** kelime → `*.hata`: `odeme.hata` ✔, `stok.hata` ✔, `odeme.cok.hata` ✘
- `#` = **sıfır ya da daha çok** kelime → `#` her şeye uyar, `odeme.#` "odeme ile başlayan her şey".

Örnek: bir kuyruk sadece **hataları**, öteki **her şeyi** toplasın:
```
odeme.hata  ─┐                 ┌─ "*.hata" ─► [atolye.hatalar]
odeme.bilgi ─┼─► [topic ex] ───┤
stok.hata   ─┘                 └─ "#"      ─► [atolye.tum]
```
Her mesaj, **uyan her binding'in** kuyruğuna girer (bir mesaj birden çok kuyruğa gidebilir). Hiçbir desen uymazsa mesaj kaybolur.

§ADIM Ölü mektup kutusu (DLX) ve zaman aşımı (TTL) | cs
§ANLAT
İşlenemeyen mesaj **çöpe gitmesin**: ayrı bir "ölü mektup kutusu"na düşsün, sonra incelenir. Bir mesaj şu durumlarda "ölür":
1. Tüketici onu **reddeder** (`BasicNackAsync(..., requeue: false)`),
2. **süresi dolar** (`x-message-ttl`, milisaniye),
3. kuyruk uzunluk sınırını aşar.

Kurulum 3 parça:
```
[atolye.is2] ──(ölürse: x-dead-letter-exchange)──► [atolye.olu exchange] ──► [atolye.olu-kutusu]
```
1. Ölü mektup **exchange'i + kutusu** (fanout, binding'i boş etiketle).
2. Asıl kuyruğa **argüman** yaz: `x-dead-letter-exchange` (ölünce nereye) ve `x-message-ttl` (kaç ms bekleyebilir). Argümanlar bir sözlüktür:
```csharp
var arguman = new Dictionary<string, object?>
{
    ["x-dead-letter-exchange"] = "atolye.olu",
    ["x-message-ttl"] = 2000
};
await kanal.QueueDeclareAsync("atolye.is2", durable: true, exclusive: false, autoDelete: false, arguments: arguman);
```
3. Reddet: önce `BasicGetAsync` ile mesajı al, sonra `BasicNackAsync(tag, multiple: false, requeue: false)`: "işleyemedim, geri koyma". `requeue: true` deseydin mesaj aynı kuyruğa geri dönerdi.

Süresi dolan mesajı birinin alması gerekmez: RabbitMQ kendisi taşır. `Task.Delay(3000)` ile TTL'nin dolmasını beklersin.

§ADIM Projede nasıl yapılır: MassTransit consumer | cs
§ANLAT
Yukarıda bağlantı, kanal, ack ve hata yönetimini **elle** yazdın. **MassTransit** bunların hepsini senin yerine yapan kütüphanedir: sen sadece **mesaj tipi** (bir `record`) ve onu işleyen **consumer sınıfı** yazarsın. Bu projede böyle yapılır.
- Metot **hatasız biterse** MassTransit mesajı **ack**'ler (az önce `BasicAckAsync`'i elle verdiğin gibi).
- **Hata fırlatırsa** mesaj yeniden denenir (bir sonraki adım).
- **Hatayı `try/catch` ile yutma**: yutarsan sistem "başarılı" sanır, mesaj sessizce kaybolur.
Bu adım sadece kod yazma pratiği; sayfada çalıştırılamaz (MassTransit uygulama içinde çalışır), **Kontrol et** ile doğrulanır.

    public async Task Consume(ConsumeContext<SiparisAlindi> context)

    }
}

§SORU Bağlantı (Connection) ile kanal (Channel) farkı nedir? Neden ikisi var?
Bağlantı RabbitMQ'ya açılan tek TCP hattıdır (pahalı, uygulama başına genelde 1). Kanal o hattın içindeki hafif sanal hattır; kuyruk açma, mesaj gönderme/alma gibi tüm işler kanaldan yapılır. Her iş için yeni TCP hattı açmak yavaş olduğu için tek bağlantıda çok kanal kullanılır. Kanal iş parçacıkları arasında paylaştırılmaz.
§SORU QueueDeclare ne yapar? İki kez çağırırsan ne olur?
Kuyruk yoksa oluşturur, varsa aynı ayarlarla olduğunu doğrular (idempotent). Farklı ayarla (örneğin durable farklı) çağırırsan RabbitMQ hata verir. durable: true kuyruğun RabbitMQ yeniden başlayınca da kalmasını sağlar.
§SORU Varsayılan exchange nedir?
Adı boş olan özel direct exchange. Her kuyruk ona kendi adıyla bağlıdır; routingKey = kuyruk adı verirsen mesaj doğrudan o kuyruğa gider.
§SORU BasicGet ile Consumer (BasicConsume) farkı?
BasicGet pull: sen sorarsın, tek mesaj gelir; verimsizdir, testte kullanılır. Consumer push: RabbitMQ mesaj geldikçe sana yollar; gerçek uygulamalar bunu kullanır.
§SORU Ack, nack ve reject farkı? autoAck: true neden tehlikeli?
Ack "işledim, sil". Nack/reject "işleyemedim"; requeue: true ile kuyruğa geri konur, false ile ölü mektup exchange'i varsa oraya gider yoksa silinir. autoAck: true mesajı teslim edilir edilmez siler; consumer işin ortasında çökerse mesaj sonsuza dek kaybolur.
§SORU Exchange tipleri nelerdir ve farkları?
direct: routing key birebir. fanout: bağlı tüm kuyruklara kopya (anahtara bakmaz). topic: * (bir kelime) ve # (sıfır/çok kelime) ile desen. headers: mesaj başlıklarına göre.
§SORU Yanlış routing key ile mesaj yollarsan ne olur?
Mesaj hiçbir kuyruğa ulaşmaz ve sessizce kaybolur (hata yok). Önlem: mandatory bayrağı + BasicReturn olayı ya da bağları doğrulamak.
§SORU Mesajın RabbitMQ yeniden başlayınca kaybolmaması için ne gerekir?
Üçü birden: kuyruk durable, mesaj persistent (delivery_mode 2) ve consumer'da ack doğru verilmeli. Biri eksikse mesaj kaybolabilir.
§SORU At-most-once, at-least-once, exactly-once farkı? Neden idempotency?
At-most-once kayıp olabilir, at-least-once tekrar olabilir, exactly-once pratikte zor. RabbitMQ at-least-once teslim eder; aynı mesaj iki kez gelebilir, bu yüzden işlem tekrar edildiğinde zarar vermeyecek şekilde (idempotent) yazılmalı. Projede iş fişi Bekliyor → İşleniyor atomik geçişiyle bunu sağlar.
§SORU Dead-letter queue nedir? Poison message nedir?
İşlenemeyen mesajların aktarıldığı kuyruk. Poison message, sürekli hata verip kuyruğu tıkayan mesajdır; retry sonrası DLQ/_error kuyruğuna alınarak diğer mesajlar akmaya devam eder. Mesaj reddedilince ya da TTL dolunca RabbitMQ başlığa nedenini yazar (x-death: rejected/expired).
§SORU Send ile Publish farkı (MassTransit)?
Send belirli bir kuyruğa gider, tüketici yoksa bile mesaj kuyrukta bekler. Publish mesaj tipine abone exchange'e gider; abone yoksa mesaj kaybolur. Bu yüzden projede queue:ai-istegi'ne Send kullanıldı.
§SORU RabbitMQ ile Kafka farkı (kısaca)?
RabbitMQ akıllı broker: yönlendirme, ack, kuyruk modeli; mesaj tüketilince silinir. Kafka log tabanlı: mesajlar saklanır, tüketiciler offset ile tekrar okuyabilir; çok yüksek hacim ve olay akışı için.

§ADIM İki anahtar: hangisi nerede? | txt
§ANLAT
Sistemde iki anahtar vardır: **master key** (LiteLLM'e erişim izni) ve **Anthropic API anahtarı** (gerçek sağlayıcı). Güvenlik ilkesi: sağlayıcı anahtarı **tek yerde** (LiteLLM) durur.
§ORNEK
Bir sızıntıda, uygulamaya verilen anahtar LiteLLM master key olursa hasar sınırlıdır; sağlayıcı anahtarı hiç dışarı çıkmamıştır.
§GOREV
Uygulamaya (ve LangFlow'a) hangi anahtar verilir, Anthropic anahtarı nerede durur? Tek cümleyle yaz; cevapta `master` ve `LiteLLM` geçsin.
§BASLANGIC
cevap:
§K Master key'den söz edildi ⟫ /master/i ⟫ uygulamaya LiteLLM master key verilir
§K LiteLLM'den söz edildi ⟫ /litellm/i ⟫ Anthropic anahtarı yalnızca LiteLLM'de durur
§K Anthropic anahtarı da anıldı ⟫ /anthropic/i ⟫ gerçek sağlayıcı anahtarı (Anthropic) nerede duruyor?
§COZUM
Uygulamaya LiteLLM master key verilir; Anthropic anahtarı yalnızca LiteLLM'in ortam değişkeninde durur.

§SORU LLM gateway/proxy neden kullanılır?
Tek API (OpenAI uyumlu) arkasında birçok sağlayıcı; sağlayıcı anahtarını gizleme; takma ad ile model değiştirme; maliyet ve kullanım takibi; fallback, retry ve rate limit.
§SORU Token nedir, maliyet nasıl hesaplanır? Neden özetlemede küçük model?
Token, modelin işlediği metin parçasıdır. Maliyet = giriş token'ı × giriş fiyatı + çıkış token'ı × çıkış fiyatı. Ölçtük: `hizli` (Haiku) küçük bir istekte `akilli`'dan yaklaşık **20 kat ucuz**; özetleme gibi basit işlerde ucuz model yeterlidir.
§SORU Alias (model_name) ile gerçek model ayrımının faydası?
Kod `akilli` der; model değişince (yeni sürüm, başka sağlayıcı) sadece config değişir, kod ve dağıtım değişmez.
§SORU Master key ile sağlayıcı anahtarı farkı?
Master key LiteLLM'e erişimi sağlar ve uygulamalara verilir. Sağlayıcı anahtarı (Anthropic) yalnızca LiteLLM'de durur; sızarsa en geniş zararı verir, o yüzden tek yerde tutulur.
§SORU Fallback ve retry nasıl kurulur?
LiteLLM `router_settings`/`fallbacks` ile bir model hata verirse yedeğine geçer; `num_retries` ile aynı istek tekrar denenir. Her çağrıya `request_timeout` konur.

§LAB 07 | AI Memory | LLM hafızasızdır: son N mesaj + özet + süzülmüş uzun hafıza mantığını sen yaz.

§ADIM Kayan pencere: SonN | cs
§ANLAT
LLM **hafızasızdır**: her istekte geçmişi SEN gönderirsin. Geçmiş büyüdükçe token ve maliyet artar (ölçtük: 0/4/12 mesaj → 56/216/536 token). **Sliding window**: sadece son N mesajı gönder. Sınır durumları (n > sayı, n ≤ 0) bug'ın en çok çıktığı yerdir.
§ORNEK
public static IReadOnlyList<string> IlkN(IReadOnlyList<string> liste, int n)
{
    if (n <= 0) return Array.Empty<string>();
    return liste.Take(n).ToList();
}
§GOREV
`SonN` metodunu yaz: listenin **son** `n` elemanını sırayı bozmadan döndür; `n` sayıdan büyükse hepsini, `n <= 0` ise boş liste döndür.
§BASLANGIC

{
    public static IReadOnlyList<string> SonN(IReadOnlyList<string> mesajlar, int n)
    {
        // yaz
    }
}
§K İmza doğru ⟫ /static\s+IReadOnlyList<string>\s+SonN\(\s*IReadOnlyList<string>\s+\w+\s*,\s*int\s+n\s*\)/ ⟫ public static IReadOnlyList<string> SonN(IReadOnlyList<string> mesajlar, int n)
§K n <= 0 koruması ⟫ /n\s*<=\s*0/ ⟫ if (n <= 0) return Array.Empty<string>();
§K Son n eleman alınıyor ⟫ /TakeLast\(\s*n\s*\)|Skip\(/ ⟫ mesajlar.TakeLast(n) veya Skip(sayı - n)
§K Liste döndürülüyor ⟫ /\.ToList\(\)|\.ToArray\(\)|return\s+new\s+List/ ⟫ sonucu .ToList() ile listeye çevir

§ADIM Uzun süreli hafıza filtresi | cs
§ANLAT
Uzun süreli hafıza, konuşmadan çıkarılan kalıcı gerçeklerdir ("kullanıcı kahve sever"). Bunları **modelin kendisi üretir** ve model güvenilmez bir kaynaktır: "YOK" yazar, roman yazar, aynısını tekrarlar. Veritabanına girmeden **süzülmelidir**. (Projede `HafizaServisi` aynı kuralları uygular.)
§ORNEK
var gorulen = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
if (gorulen.Add(s)) sonuc.Add(s);   // aynı metin ikinci kez eklenmez
§GOREV
`HafizaFiltrele(adaylar)`: her adayı `Trim()` et; şunları ele: **boş**, **"YOK"** (büyük/küçük harf fark etmez), **200 karakterden uzun**, **birden çok satırlı**; **tekrarları** (büyük/küçük harf farkıyla bile) ele, ilk görüneni koru.
§BASLANGIC
public static IReadOnlyList<string> HafizaFiltrele(IEnumerable<string> adaylar)
{
    // yaz
}
§K Tekrar için HashSet ⟫ /HashSet<string>/ ⟫ new HashSet<string>(StringComparer.OrdinalIgnoreCase)
§K Büyük/küçük harf duyarsız ⟫ /StringComparer\.OrdinalIgnoreCase/ ⟫ StringComparer.OrdinalIgnoreCase kullan
§K Trim() ⟫ /Trim\(\)/ ⟫ aday.Trim()
§K "YOK" ele ⟫ /["']YOK["']/ ⟫ "YOK" ile karşılaştır (Equals(..., OrdinalIgnoreCase))
§K 200 karakter sınırı ⟫ /200/ ⟫ s.Length > 200
§K Çok satırlıyı ele (\n) ⟫ /\\n/ ⟫ s.Contains('\n') (ve istersen '\r')
§K Sonuca ekleme (Add) ⟫ /\.Add\(/ ⟫ sonuc.Add(s) ile geçerleri topla
§COZUM
public static IReadOnlyList<string> HafizaFiltrele(IEnumerable<string> adaylar)
{
    var gorulen = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
    var sonuc = new List<string>();
    foreach (var aday in adaylar)
    {
        var s = (aday ?? "").Trim();
        if (s.Length == 0 || s.Length > 200) continue;
        if (s.Equals("YOK", StringComparison.OrdinalIgnoreCase)) continue;
        if (s.Contains('\n') || s.Contains('\r')) continue;
        if (gorulen.Add(s)) sonuc.Add(s);
    }
    return sonuc;
}

§SORU LLM neden "hafızasız"? Context window nedir, dolarsa ne olur?
Model her istekte sadece o istekteki metni görür; önceki konuşmayı sen göndermezsen bilmez. Context window, tek istekte işleyebildiği toplam token sınırıdır; dolarsa istek reddedilir ya da eski kısım atılmak zorunda kalır, bu yüzden pencere + özet kullanılır.
§SORU Sliding window ile özetleme (summarization) farkı, neden ikisi birlikte?
Pencere son mesajları **aynen** tutar (ayrıntı korunur, ucuz). Özet eski kısmı **sıkıştırır** (bilgi kaybı olur ama bağlam yaşar). İkisi birlikte: özet + son N mesaj hem ucuz hem bağlamlıdır.
§SORU Kısa ve uzun süreli hafıza nerede saklanır, nasıl geri çağrılır?
Kısa süreli: konuşma geçmişi (projede MongoDB `mesajlar`). Uzun süreli: kalıcı gerçekler (MongoDB `hafiza`; ölçek büyürse vektör veritabanı + benzerlik araması ile ilgili olanlar getirilir) ve her istekte prompt'a eklenir.
§SORU Modelin ürettiği hafızaya neden güvenmemeliyiz?
Model çıktısı güvenilmez girdidir: çöp ("YOK"), uzun metin, tekrar ya da **prompt injection** ile enjekte edilmiş talimat içerebilir. Süzülmeden saklanırsa kalıcı hâle gelir.
§SORU Hafıza silme/görüntüleme neden bir özellik olmalı?
Kişisel veri saklıyorsun: kullanıcı neyin tutulduğunu görmeli ve silebilmeli (KVKK/GDPR "unutulma hakkı"). Projede `GET/DELETE /api/hafiza` bu yüzden var.
