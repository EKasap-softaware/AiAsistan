§CIKTI 02-0
Gerçek çalıştırma çıktısı (hash'ler ve klasör yolu sende farklı olur):
```
$ git init -b main
Initialized empty Git repository in .../.git/
$ echo "ilk not" > notlar.txt
$ git add notlar.txt
$ git commit -m "feat: notlar eklendi"
[main (root-commit) 0fe5054] feat: notlar eklendi
 1 file changed, 1 insertion(+)
 create mode 100644 notlar.txt
```
`0fe5054` = commit'in kısa kimliği (hash). `root-commit` = bu deponun ilk commit'i.

§CIKTI 02-1
Gerçek çalıştırma çıktısı:
```
$ git switch -c ozellik/selam
Switched to a new branch 'ozellik/selam'
$ git switch main
Switched to branch 'main'
$ git merge --no-ff ozellik/selam
Merge made by the 'ort' strategy.
 selam.txt | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 selam.txt
$ git log --oneline --graph
*   9f1b4f0 Merge branch 'ozellik/selam'
|\
| * 8a62fb8 feat: selam dosyasi
|/
* 0fe5054 feat: notlar eklendi
```
Grafikte dalın ayrılıp **merge commit** ile birleştiğini görürsün. `--no-ff` olmasaydı bu "çatal" görünmezdi.

§CIKTI 02-2
İki dal aynı dosyayı değiştirince gerçekten olan (çıktı):
```
$ git merge ozellik/b
Auto-merging r.txt
CONFLICT (add/add): Merge conflict in r.txt
Automatic merge failed; fix conflicts and then commit the result.
$ cat r.txt
<<<<<<< HEAD
renk: AAA
=======
renk: BBB
>>>>>>> ozellik/b
```
Git "çakıştı" der ve dosyaya işaretleri koyar. İşaretleri silip metni düzeltirsin, sonra `git add` + `git commit`.

§CIKTI 02-3
Gerçek çalıştırma çıktısı:
```
$ git revert 8a62fb8 --no-edit
[main c766fb2] Revert "feat: selam dosyasi"
 1 file changed, 1 deletion(-)
 delete mode 100644 selam.txt
$ git log --oneline
c766fb2 Revert "feat: selam dosyasi"
9f1b4f0 Merge branch 'ozellik/selam'
0fe5054 feat: notlar eklendi
8a62fb8 feat: selam dosyasi
```
Eski commit (`8a62fb8`) **silinmedi**; üstüne tersini yapan yeni commit (`c766fb2`) eklendi. Geçmiş korundu.

§CIKTI 04-0
Gerçek mongosh çıktısı (`ObjectId` değerleri sende farklı olur):
```
> db.siparisler.insertMany([ ...3 belge... ])
{
  acknowledged: true,
  insertedIds: {
    '0': ObjectId('6b007e56f7913ba711b388fa'),
    '1': ObjectId('6b007e56f7913ba711b388fb'),
    '2': ObjectId('6b007e56f7913ba711b388fc')
  }
}
```
`acknowledged: true` = yazıldı. Her belgeye Mongo otomatik bir `_id` (ObjectId) verdi.

§CIKTI 04-1
Gerçek mongosh çıktısı:
```
> db.siparisler.find({ tutar: { $gt: 100 }, durum: 'bekliyor' }).sort({ tutar: -1 })
[
  { _id: ObjectId('...'), musteri: 'Ali', tutar: 120, durum: 'bekliyor' }
]
```
3 belgeden **sadece Ali** döndü: Ayşe 80 (100'den küçük), Can 300 ama durumu `tamamlandi`. İki koşul birlikte = VE.

§CIKTI 04-2
Gerçek mongosh çıktısı:
```
> db.siparisler.createIndex({ musteri: 1 })
musteri_1
> db.siparisler.createIndex({ durum: 1, tutar: -1 })
durum_1_tutar_-1
> db.siparisler.getIndexes().map(i => i.name)
[ '_id_', 'musteri_1', 'durum_1_tutar_-1' ]
```
Index adı alan+yön'den üretilir. `_id_` Mongo'nun kendi index'i.

§CIKTI 04-3
Gerçek mongosh çıktısı:
```
> db.siparisler.createIndex({ olusturulma: 1 }, { expireAfterSeconds: 3600 })
olusturulma_1
```
Artık `olusturulma` (Date) alanı 1 saati geçen belgeler otomatik silinir (Mongo dakikada bir temizler).

§CIKTI 04-4
Gerçek mongosh çıktısı:
```
> db.siparisler.aggregate([ { $group: ... }, { $out: 'musteri_toplam' } ])
(çıktı yok: sonuç musteri_toplam koleksiyonuna yazıldı)
> db.musteri_toplam.find().sort({ _id: 1 })
[
  { _id: 'Ali', toplam: 120 },
  { _id: 'Ayse', toplam: 80 },
  { _id: 'Can', toplam: 300 }

```
`$group` her müşteriyi tek satıra topladı; `$out` yeni bir koleksiyon oluşturdu.

§CIKTI 04-5
Gerçek mongosh çıktısı:
```
> db.siparisler.updateOne({ musteri: 'Can' }, { $set: { durum: 'tamamlandi', guncellenme: new Date() } })
{ acknowledged: true, matchedCount: 1, modifiedCount: 1, upsertedCount: 0 }
> db.siparisler.find({ musteri: 'Can' })
[ { _id: ObjectId('...'), musteri: 'Can', tutar: 300, durum: 'tamamlandi',
    guncellenme: ISODate('2026-01-01T00:00:00.000Z') } ]
```
`matchedCount: 1` (1 belge bulundu), `modifiedCount: 1` (1 belge değişti). Belgeye yeni `guncellenme` alanı eklendi.

§CIKTI 05-0
Gerçek çalıştırma çıktısı:
```
Bağlantı açık mı: True
Kanal açık mı: True, kanal no: 1

── Sonuç: RabbitMQ'da şu an ne var? ──

İlk iki satır sonucu: bağlantı da kanal da açık. `kanal no: 1` bu bağlantıdaki ilk kanal demek; ikinci kanal açsaydın 2 olurdu. Alttaki tablo boş, çünkü henüz kuyruk açmadın.

§CIKTI 05-1
Gerçek çalıştırma çıktısı:
```
Gönderildi: siparis-1
Gönderildi: siparis-2
Kuyrukta bekleyen mesaj: 2

── Sonuç: RabbitMQ'da şu an ne var? ──
kuyruk    atolye.siparis             bekleyen: 2  işlenmekte(ack bekliyor): 0
```
Sondaki sayı **2**: iki mesaj kuyrukta bekliyor. Alttaki tabloda `bekleyen: 2` aynı bilgi, bu kez RabbitMQ'nun kendi gözünden. Program bitti ama mesajlar durable kuyrukta durur; sayfa en sonda hepsini temizler.

§CIKTI 05-2
Gerçek çalıştırma çıktısı:
```
[hazır] atolye.is kuyruğunda 3 mesaj bekliyor.
BasicGet ile alındı: siparis-1
Consumer ile alındı: siparis-2
Consumer ile alındı: siparis-3
[sonuç] Kuyrukta bekleyen mesaj: 0  -> hiç mesaj kalmadı (hepsi ack'lendi ya da reddedildi) ✔

── Sonuç: RabbitMQ'da şu an ne var? ──
kuyruk    atolye.is                  bekleyen: 0  işlenmekte(ack bekliyor): 0
```
Üç mesaj sırayla alındı: biri `BasicGet` ile (çekme), ikisi consumer ile (dinleme). Hepsine ack verildiği için kuyrukta bekleyen kalmadı. `BasicAckAsync` satırını silip tekrar çalıştırırsan son satır `3` olur: mesajlar geri döner.

§CIKTI 05-3
Gerçek çalıştırma çıktısı:
```
kargo kuyruğu : 1 mesaj
fatura kuyruğu: 0 mesaj

── Sonuç: RabbitMQ'da şu an ne var? ──
exchange  atolye.siparisler          tip: direct
kuyruk    atolye.fatura              bekleyen: 0  işlenmekte(ack bekliyor): 0
kuyruk    atolye.kargo               bekleyen: 1  işlenmekte(ack bekliyor): 0
bağ       atolye.siparisler  --[fatura]-->  atolye.fatura
bağ       atolye.siparisler  --[kargo]-->  atolye.kargo
```
`kargo` etiketli mesaj yalnızca `atolye.kargo`'ya girdi. `yok` etiketli mesaj **hiçbir yerde yok**: hata da vermedi. Alttaki tablodaki `bağ` satırları exchange'in kurallarını gösterir.

§CIKTI 05-4
Gerçek çalıştırma çıktısı:
```
atolye.eposta: 1 mesaj
atolye.istatistik: 1 mesaj

── Sonuç: RabbitMQ'da şu an ne var? ──
exchange  atolye.olaylar             tip: fanout
kuyruk    atolye.eposta              bekleyen: 1  işlenmekte(ack bekliyor): 0
kuyruk    atolye.istatistik          bekleyen: 1  işlenmekte(ack bekliyor): 0
bağ       atolye.olaylar  --[]-->  atolye.eposta
bağ       atolye.olaylar  --[]-->  atolye.istatistik
```
Tek `BasicPublishAsync` çağırdın, iki kuyrukta da 1 mesaj var: fanout her bağlı kuyruğa kopya atar. Bağlardaki `[]` boş etikettir (fanout bakmaz).

§CIKTI 05-5
Gerçek çalıştırma çıktısı:
```
hatalar: 2 mesaj
tum    : 3 mesaj

── Sonuç: RabbitMQ'da şu an ne var? ──
exchange  atolye.log                 tip: topic
kuyruk    atolye.hatalar             bekleyen: 2  işlenmekte(ack bekliyor): 0
kuyruk    atolye.tum                 bekleyen: 3  işlenmekte(ack bekliyor): 0
bağ       atolye.log  --[*.hata]-->  atolye.hatalar

§CIKTI 05-6
Gerçek çalıştırma çıktısı:
```
Reddedildi: is-1
3 sn bekleniyor (is-2'nin süresi dolsun)...
Ölü mektup kutusunda: 2 mesaj

── Sonuç: RabbitMQ'da şu an ne var? ──
exchange  atolye.olu                 tip: fanout
kuyruk    atolye.is2                 bekleyen: 0  işlenmekte(ack bekliyor): 0   [x-dead-letter-exchange=atolye.olu, x-message-ttl=2000]
kuyruk    atolye.olu-kutusu          bekleyen: 2  işlenmekte(ack bekliyor): 0
bağ       atolye.olu  --[]-->  atolye.olu-kutusu
```
İki mesaj da ölü mektup kutusunda: `is-1`'i sen reddettin, `is-2`'nin süresi doldu. Tablodaki `x-dead-letter-exchange` ve `x-message-ttl` asıl kuyruğun argümanlarıdır.

§CIKTI 06-2
Gerçek LiteLLM yanıtı:
```
POST /v1/chat/completions (model=hizli) -> 200
cevap : Tamam, ne yazmamı istersin? Bir konu, metin türü (e-posta, şiir, hikâye, rapor vb.)
        veya uzunluk tercihi söylersen hemen başlayabilirim.
usage : 14 giriş + 148 çıkış token
Anahtarsız istek -> 401
```
- `usage` = fatura: 14 token girdi, 148 token çıktı.
- **`401`** = Authorization başlığı yoksa kapı kapalı.
- Dikkat: `max_tokens: 30` ile denediğimde cevap **boş (None)** geldi: model, sınır dolunca yarıda kesildi. Çok küçük `max_tokens` cevabı boğar.
