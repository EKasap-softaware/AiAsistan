§NASIL 03-3
**Boş sayfadan başla, şu sırayla yaz (her parça bir önceki üzerine eklenir):**

**1) En üstte iki satır — "servisler" başlığı ve servisin adı**
```yaml
services:
  web:
```
`web:` iki boşluk içeride. YAML'da **girinti = aitlik**: içerideki satır, üstündekine bağlı olur. (TAB kullanma, boşluk kullan.)

**2) `web`'in altına 4 boşlukla özelliklerini ekle**
```yaml
    build: .
```
`.` = "Dockerfile'ı bu klasörde bul, imajı buradan derle".

**3) Port — "DIŞ:İÇ" kuralı**
```yaml
    ports: ["18098:8000"]
```
Soldaki sayı **senin bilgisayarının** portu, sağdaki **konteynerin içindeki**. Görev "18098 → 8000" dedi, sırayı ters yazma.

**4) Ortam değişkeni**
```yaml
    environment:
      MESAJ: "istedigin bir metin"
```
`environment:` altına **6 boşlukla** `ANAHTAR: "değer"`.

**5) Volume bağla (konteynerin içine)**
```yaml
    volumes:
      - veri:/veri
```
`veri:/veri` = "`veri` adlı volume'ü konteynerde `/veri` yoluna bağla". Başında `- ` (tire + boşluk) liste elemanı demek.

**6) En altta, `services:` ile AYNI hizada (girintisiz) volume'ü tanımla**
```yaml
volumes:
  veri:
```
Bunu unutursan Docker "veri diye volume yok" der. Hizaya dikkat: `services:` ve `volumes:` aynı sütunda başlar.

> Takıldıysan: yukarıdaki 6 parçayı sırayla alt alta kopyala = çözüm. Sonra kapat, baştan kendin yaz.

Cevap kalıbı: **`servis-adı:port`** → yazman gereken tek satır `mongo:27017`.

§NASIL 04-4
**Hedef:** müşteri başına toplam, sonucu yeni koleksiyona yaz.

| Parça | Anlamı |
|---|---|
| `rabbitmqadmin` | RabbitMQ'nun komut satırı aracı |

3. Bak ama silme: `rabbitmqadmin get messages --queue atolye.siparis --ack-mode ack_requeue_true`

§NASIL 05-1
**Hedef:** exchange + iki kuyruk + iki bağ + iki mesaj (biri doğru, biri yanlış anahtar).

Sırayı ezberle: **önce exchange, sonra kuyruklar, sonra bağlar, en son mesaj.** Bağ kurmadan mesaj yollarsan mesaj kaybolur.

| Komut | Ne yapar |
|---|---|
| `declare exchange --name X --type direct` | postacıyı oluştur (`direct` = anahtar birebir eşleşsin) |
| `declare queue --name K --durable true` | kutuyu oluştur |
| `declare binding ...` | kuralı yaz (aşağıda) |
| `publish message --exchange X --routing-key A --payload P` | mesajı postacıya ver |

**Bağ komutunun 4 parçası** (en çok yanlış yazılan satır):
- `--source atolye.siparisler` → hangi exchange'den geliyor
- `--destination-type queue` → hedef bir kuyruk
- `--destination atolye.kargo` → hangi kuyruğa gidecek
- `--routing-key kargo` → hangi anahtarla gelen mesaj

```
rabbitmqadmin declare binding --source atolye.siparisler --destination-type queue --destination atolye.kargo --routing-key kargo
```
Fatura için aynı satırı kopyala; `atolye.kargo` ve `kargo` yerine `atolye.fatura` ve `fatura` yaz.

**Sonucu oku:** `atolye.kargo` kuyruğunda `bekleyen: 1`, `atolye.fatura`'da `0` olmalı. Yanlış anahtarlı mesaj için `⚠ KAYBOLDU` uyarısı çıkar; hata mesajı gelmez, RabbitMQ'nun sessiz davranışı budur.

**Hedef:** `*.hata` yalnızca hataları, `#` her şeyi toplasın.

| Desen | Neyle eşleşir | Eşleşmez |
|---|---|---|
| `*.hata` | `odeme.hata`, `stok.hata` | `odeme.bilgi`, `a.b.hata` |

4. Üç mesaj (anahtar sırasıyla): `odeme.hata` → m1, `odeme.bilgi` → m2, `stok.hata` → m3.

```
rabbitmqadmin publish message --exchange atolye.log --routing-key odeme.hata --payload m1
```
**Sonucu oku:** hatalar = 2 (m1, m3), tum = 3. Hesabı kendin yap: `odeme.bilgi` `*.hata`'ya uymaz, ama `#` her şeye uyar.

§NASIL 05-5
**Hedef:** 5 satırlık consumer. `ch` ve `kuyruk` hazır geliyor.

1. Consumer nesnesi: `var tuketici = new AsyncEventingBasicConsumer(ch);` → "bu kanalda mesaj dinleyecek nesne".
2. Mesaj gelince çalışacak kod: `tuketici.ReceivedAsync += async (_, ea) => { ... };`
   - `+=` "bu olaya şu kodu ekle" demek. `_` kullanmadığın ilk parametre, `ea` mesajın kendisi.
3. Süslü parantez içinde 3 iş:
   - gövdeyi metne çevir: `var metin = Encoding.UTF8.GetString(ea.Body.ToArray());` (mesaj byte dizisi olarak gelir)
   - yazdır: `Console.WriteLine($"Alındı: {metin}");`
   - **ack**: `await ch.BasicAckAsync(ea.DeliveryTag, multiple: false);` (`DeliveryTag` = mesajın numarası)
4. Dinlemeyi başlat: `await ch.BasicConsumeAsync(kuyruk, autoAck: false, consumer: tuketici);`
```csharp
var tuketici = new AsyncEventingBasicConsumer(ch);
tuketici.ReceivedAsync += async (_, ea) =>
{
    var metin = Encoding.UTF8.GetString(ea.Body.ToArray());
    Console.WriteLine($"Alındı: {metin}");
    await ch.BasicAckAsync(ea.DeliveryTag, multiple: false);
};
await ch.BasicConsumeAsync(kuyruk, autoAck: false, consumer: tuketici);
```
Deney: ack satırını sil, ▶ Çalıştır'a bas; mesajların kuyruğa geri döndüğünü göreceksin. Sonra geri ekle.

§NASIL 07-0
**Hedef:** son `n` mesajı döndür.

Düşün: boş/negatif n → boş liste; yoksa son n eleman.

1. Koruma (erken çıkış): `if (n <= 0) return Array.Empty<string>();`
2. Asıl iş: `mesajlar.TakeLast(n)` = **son n** eleman (n listeden büyükse hepsini verir, hata atmaz).
3. Sonucu listeye çevir: `.ToList()`
```csharp
public static IReadOnlyList<string> SonN(IReadOnlyList<string> mesajlar, int n)
{
    if (n <= 0) return Array.Empty<string>();
    return mesajlar.TakeLast(n).ToList();
}
```
`Take(n)` = ilk n, `TakeLast(n)` = **son** n — karıştırma.

§NASIL 07-2
**Hedef:** filtre. Önce **boş iki araç** kur, sonra döngüyle süz.

1. Tekrar kontrolü için: `var gorulen = new HashSet<string>(StringComparer.OrdinalIgnoreCase);` (büyük/küçük harf fark etmez)
2. Sonuç listesi: `var sonuc = new List<string>();`
3. Her aday için döngü: `foreach (var aday in adaylar) { ... }`
4. Döngünün içinde sırayla:
   - temizle: `var s = (aday ?? "").Trim();`
   - boş veya >200 ise **atla**: `if (s.Length == 0 || s.Length > 200) continue;`
   - "YOK" ise atla: `if (s.Equals("YOK", StringComparison.OrdinalIgnoreCase)) continue;`
   - çok satırlıysa atla: `if (s.Contains('\n') || s.Contains('\r')) continue;`
   - ilk kez görülüyorsa ekle: `if (gorulen.Add(s)) sonuc.Add(s);`  (`Add` daha önce varsa `false` döner)
5. En sonda `return sonuc;`

`continue` = "bu adayı bırak, sonrakine geç".

§NASIL 09-1
Yukarıdan aşağı, her seviye 2 boşluk içeride:
```yaml
jobs:                       # 0 boşluk
  test:                     # 2  → job adı
    runs-on: ubuntu-latest  # 4  → hangi makine
    steps:                  # 4
      - uses: actions/checkout@v4          # 6  → önce kodu indir
      - uses: actions/setup-dotnet@v4      # 6  → sonra .NET kur
        with:                              # 8  (tire'den 2 sonra)
          dotnet-version: 9.0.x            # 10
```
- `- uses:` = hazır eylem çalıştır. `with:` o eylemin ayarları.
- `with:` hizası `uses:`'ın **u**'su ile aynı olmalı (tireden sonra).
- **Sıra**: checkout önce, setup-dotnet sonra.

§NASIL 09-2
Verilen kodu 2 yerde genişlet:

1. `with:` altına bir satır ekle (`dotnet-version` ile aynı hiza): `cache: true`
2. `steps:` listesinin sonuna **iki** yeni adım (tire `- uses:` ile aynı hizada):
   - `- run: dotnet build --no-restore -c Release`
   - `- run: dotnet test --no-build -c Release`

`run:` = kabuk komutu. Sıra: **build önce, test sonra**. `--no-build` = "zaten derledim, tekrar derleme".
```yaml
        with:
          dotnet-version: 9.0.x
          cache: true
      - run: dotnet build --no-restore -c Release
      - run: dotnet test --no-build -c Release
```

§NASIL 09-3
Verilen dosyaya 3 şey ekle:

1. `on:` bloğundan sonra, **girintisiz**:
```yaml
permissions:
  contents: read
```
2. Hemen altına:

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
```

Hepsi birleşince: `permissions` ve `concurrency` **dosya seviyesinde** (0 boşluk), `timeout-minutes` **job içinde** (4 boşluk).

§NASIL 09-4
Adımın altına `env:` ekle, `run:` ile **aynı hizada**:

§NASIL 10-0
Dosyanın yapısı iki kısım: **frontmatter** + **gövde**.

1. Başlangıç `---` ile aç.
2. `name: test-yaz` (klasör adıyla aynı).
3. `description:` — en az 50 karakter, ne yaptığını **ve ne zaman** kullanılacağını söyle: "Yeni bir servis sınıfı için unit test yazarken kullan. ...".

